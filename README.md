# ระบบบริหารจัดการเครื่องปรับอากาศ ITEL

> ⚠️ **ไฟล์นี้ยังอธิบายการติดตั้งแบบเก่าที่ใช้ Google Sheets เป็นฐานข้อมูล**
> ระบบจริงใช้ SQLite แล้ว ภาพรวมที่เป็นปัจจุบันอยู่ที่ [docs/CONTEXT.md](docs/CONTEXT.md)
> และขั้นตอนติดตั้งจริงอยู่ที่ [docs/DEPLOY.md](docs/DEPLOY.md)

ย้ายจาก Google Apps Script มารันเป็นเว็บแอปปกติ โดยยังใช้ **Google Sheets เป็นฐานข้อมูลเหมือนเดิม**

---

## ทำไมถึงเร็วขึ้น

| | เดิม (Apps Script) | ใหม่ |
|---|---|---|
| จำนวนครั้งที่คุยกับ Google ต่อ 1 คำสั่ง | 20-30 ครั้ง | **2 ครั้ง** (วัดแล้ว) |
| สาเหตุหลักที่ช้า | Google เปิดสคริปต์ใหม่ทุกครั้งที่เรียก | ไม่มีขั้นตอนนี้ |
| เวลาตอบสนอง | 2-4 วินาทีต่อคลิก (จากการใช้งานจริง) | 0.5-1 วินาที ปกติ (วัดแล้ว) |

**ตัวเลขที่วัดจริง** — คำสั่งที่อ่านชีต 5 แผ่นครอบคลุมเครื่อง 457 ตัว:
เร็วสุด 0.46 วิ · ปกติราว 0.5-1 วิ · บางครั้งพุ่งถึง 4-5 วิ

ความไม่นิ่งนั้นมาจาก **Google Sheets API เองที่ตอบไม่คงที่** (วัดได้ตั้งแต่ 0.5 ถึง 5.9 วินาทีสำหรับคำขอเดียวกัน) ไม่ใช่จากโค้ดฝั่งเรา
ซึ่งพิสูจน์ได้จากการที่ระบบยิงไปหา Google แค่ 2 ครั้งต่อคำสั่ง และไม่มีการเขียนชีตแอบแฝงเลย
ถ้าวันไหนต้องการให้นิ่งกว่านี้ ทางแก้คือย้ายฐานข้อมูลออกจาก Google Sheets ไปเป็นฐานข้อมูลจริง

ข้อมูลยังอยู่ในไฟล์ Google Sheets เดิม เปิดแก้ในชีตได้ตามปกติ

## รันได้ 2 แบบ จากโค้ดชุดเดียวกัน

| แบบ | คำสั่ง | เหมาะกับ |
|---|---|---|
| **บนเครื่องตัวเอง / server บริษัท** | `npm start` | ทดลองใช้ตอนนี้ แล้วยกขึ้น cloud บริษัททีหลังโดยไม่ต้องแก้โค้ด |
| บน Cloudflare (ฟรี) | `npm run deploy` | อยากให้เข้าถึงจากที่ไหนก็ได้โดยไม่ต้องดูแลเครื่องเอง |

ตรรกะทั้งหมดอยู่ใน `src/` ซึ่งไม่รู้จักแพลตฟอร์มใดเลย ส่วนที่รู้จักแพลตฟอร์มจริงๆ อยู่ใน `platform/` ไฟล์ละตัว ตอนย้ายจึงไม่ต้องแตะตรรกะ

# ขั้นตอนติดตั้ง (รันบนเครื่องตัวเอง)

ทำครั้งเดียว ประมาณ 30 นาที

## ขั้นที่ 0 — ติดตั้ง Node.js

ยังไม่มีในเครื่องนี้ ดาวน์โหลดตัว **LTS** จาก <https://nodejs.org> แล้วติดตั้งตามปกติ (กด Next รวดเดียวได้)

ปิด PowerShell แล้วเปิดใหม่ จากนั้นตรวจว่าได้จริง:

```bash
node --version
```

ต้องขึ้นเลขเวอร์ชัน เช่น `v22.x.x` ถ้าขึ้นว่าไม่รู้จักคำสั่ง ให้รีสตาร์ทเครื่องแล้วลองใหม่

## ขั้นที่ 1 — สร้าง Service Account ของ Google

ระบบใหม่ไม่ได้รันอยู่ในบัญชี Google เหมือน Apps Script จึงต้องมี "บัญชีหุ่นยนต์" ไว้เข้าถึงชีตแทน

> ### ⚠️ ขั้นนี้ฟรี ไม่ต้องใส่บัตรเครดิต
>
> Google Cloud จะเด้งแบนเนอร์ชวน **"เริ่มทดลองใช้ฟรี / Start free / รับเครดิต $300"** อยู่ตลอด
> **ห้ามกด** เพราะปุ่มนั้นจะพาไปหน้าใส่บัตรเครดิต
>
> Google Sheets API ไม่ต้องเปิด billing เลย ให้กดปิดแบนเนอร์ทิ้งแล้วทำตามขั้นตอนข้างล่างต่อ
> ถ้าเผลอเข้าไปในหน้า "Billing" แล้ว ให้กดย้อนกลับ ไม่ต้องกรอกอะไร

1. เข้า <https://console.cloud.google.com>
   - ถ้าเจอหน้าให้ยอมรับเงื่อนไข ให้ติ๊กยอมรับได้ ตรงนี้ยังไม่ขอบัตร
2. ที่แถบบนสุด กดชื่อโปรเจกต์ → **New Project** → ตั้งชื่อ เช่น `aircon-manager` → **Create**
3. ไปที่ **APIs & Services → Library** ค้นหา **Google Sheets API** → กด **Enable**
   - ตรงนี้ต้องเปิดได้เลยโดยไม่ถามเรื่องเงิน ถ้าขึ้นว่าต้องเปิด billing แสดงว่าค้นหาเจอ API ตัวอื่นที่ไม่ใช่ ให้ย้อนกลับไปเลือกตัวที่ชื่อ **Google Sheets API** พอดีเป๊ะ
4. ไปที่ **APIs & Services → Credentials → Create Credentials → Service account**
   - ตั้งชื่อ เช่น `aircon-server` → **Create and continue** → ช่อง role **ข้ามไปเลย ไม่ต้องเลือก** → **Done**
5. คลิกที่ service account ที่เพิ่งสร้าง → แท็บ **Keys** → **Add Key → Create new key → JSON → Create**
6. ไฟล์ JSON จะถูกดาวน์โหลดมา **เก็บไว้ให้ดี อย่าอัปโหลดขึ้นที่สาธารณะ** เปิดด้วย Notepad จะเห็น 2 ค่าที่ต้องใช้:
   - `client_email` — หน้าตาเหมือน `aircon-server@xxxxx.iam.gserviceaccount.com`
   - `private_key` — ข้อความยาวๆ ขึ้นต้นด้วย `-----BEGIN PRIVATE KEY-----`

## ขั้นที่ 2 — แชร์ Google Sheet ให้ service account

เปิดไฟล์ Google Sheet ของระบบ → กด **แชร์** → วาง `client_email` จากขั้นที่แล้ว → เลือกสิทธิ์ **ผู้แก้ไข** → ส่ง

> ข้ามขั้นนี้ไม่ได้ ถ้าไม่แชร์จะขึ้น error "ไม่มีสิทธิ์เข้าถึง Google Sheet"

## ขั้นที่ 3 — ใส่ค่าตั้งค่า (มีสคริปต์ทำให้)

เปิด PowerShell ที่โฟลเดอร์โปรเจกต์ แล้วสั่ง:

```bash
powershell -ExecutionPolicy Bypass -File setup.ps1
```

สคริปต์จะทำให้ 3 อย่าง:

1. **หาไฟล์ JSON ให้เอง** — ไล่หาในโฟลเดอร์ Downloads, Desktop และโฟลเดอร์โปรเจกต์ ถ้าเจอหลายไฟล์จะให้เลือกหมายเลข
2. **ถามลิงก์ Google Sheet** — วางลิงก์เต็มจากแถบที่อยู่ของเบราว์เซอร์ได้เลย เดี๋ยวมันตัด ID ให้เอง (กด Enter เฉยๆ เพื่อใช้ไฟล์เดิม)
3. **เขียนไฟล์ `.env` ให้** พร้อมแปลงค่า `private_key` ให้ถูกรูปแบบ

พอเสร็จมันจะแสดงอีเมลของ service account ให้ — **คัดลอกอีเมลนั้นไปทำขั้นที่ 2 (แชร์ชีต)** ถ้ายังไม่ได้ทำ

```
SPREADSHEET_ID="1utgGVyDGtof8rh_fe9VtqcNPmyf61lbEkqwS6spMxc0"
```

- `GOOGLE_PRIVATE_KEY` — ค่า `private_key` ในไฟล์ JSON

**จุดที่คนพลาดบ่อยที่สุด:** ถ้าเปิดไฟล์ JSON ด้วย Notepad ค่า `private_key` จะเป็นบรรทัดเดียวที่มี `\n` (แบ็กสแลชกับตัว n) คั่นอยู่ข้างใน — ให้คัดลอกมาแบบนั้นเลย **ห้ามกด Enter แยกบรรทัด** และห้ามลบ `\n` ออก

แต่ถ้าเปิดด้วยโปรแกรมที่จัดรูปแบบ JSON ให้สวย (เช่น VS Code กด Format) มันจะแสดงเป็นหลายบรรทัดจริง อันนั้นคัดลอกมาใช้ไม่ได้ ต้องแปลงกลับเป็น `\n` ก่อน — ซึ่งคือสิ่งที่สคริปต์ทำให้

## ขั้นที่ 4 — เปิดระบบ

```bash
npm start
```

ถ้าตั้งค่าถูก จะขึ้นประมาณนี้:

```
✅ ระบบบริหารจัดการเครื่องปรับอากาศ ITEL พร้อมใช้งานแล้ว

   เครื่องนี้        http://localhost:8787
   เครื่องอื่นในวง  http://192.168.1.45:8787

   กด Ctrl+C เพื่อหยุดการทำงาน
```

เปิด <http://localhost:8787> แล้วเข้าระบบด้วยบัญชีเดิมได้เลย

## ขั้นที่ 5 — ให้คนอื่นในออฟฟิศเข้าใช้

ครั้งแรกที่รัน **Windows Firewall จะเด้งถาม** ให้กด **Allow access** โดยติ๊กที่ **เครือข่ายส่วนตัว (Private networks)**

จากนั้นแจกลิงก์บรรทัด "เครื่องอื่นในวง" ที่ขึ้นตอนเปิดระบบให้เพื่อนร่วมงาน (เช่น `http://192.168.1.45:8787`)

> เลข IP นี้อาจเปลี่ยนเมื่อรีสตาร์ทเราเตอร์ ถ้าอยากให้คงที่ ให้ขอทีม IT ตั้ง **IP แบบคงที่ (static IP)** ให้เครื่องนี้

## ขั้นที่ 6 — ให้เปิดเองตอนบูตเครื่อง (ทำหรือไม่ทำก็ได้)

ถ้าไม่ทำขั้นนี้ ทุกครั้งที่รีสตาร์ทเครื่องต้องมาสั่ง `npm start` ใหม่เอง

1. กด Win แล้วพิมพ์ **Task Scheduler** เปิดขึ้นมา
2. **Create Task** (ไม่ใช่ Create Basic Task)
3. แท็บ **General** — ตั้งชื่อ เช่น `Aircon Manager` แล้วติ๊ก **Run whether user is logged on or not**
4. แท็บ **Triggers** — **New** → Begin the task: **At startup** → OK
5. แท็บ **Actions** — **New**
   - Program: `C:\Program Files\nodejs\node.exe`
   - Add arguments: `platform/node.js`
   - Start in: `C:\Project Aircon-manager`
6. แท็บ **Settings** — ติ๊ก **If the task fails, restart every** 1 minute
7. กด OK

อย่าลืมตั้งค่าเครื่องไม่ให้ **Sleep** ด้วย (Settings → System → Power → Screen and sleep → เลือก Never)

## ขั้นที่ 7 — ตั้งค่าบริการสร้าง PDF

ทำเฉพาะถ้าต้องใช้ฟอร์มล้างแอร์ที่ออกเป็น PDF (เมนูอื่นทำงานได้ครบโดยไม่ต้องทำขั้นนี้)

1. เปิดโปรเจกต์ Apps Script เดิม (จากในชีต: **ส่วนขยาย → Apps Script**)
2. ลบโค้ดใน `Code.gs` ทิ้งทั้งหมด แล้ววางเนื้อหาจาก `apps-script/PdfService.gs` แทน
   - ไฟล์ `Index.html` ในโปรเจกต์ลบทิ้งได้เลย ไม่ใช้แล้ว
3. แก้ค่า `SHARED_SECRET` ในไฟล์ให้เป็นข้อความยาวๆ ที่เดายาก
4. เลือกฟังก์ชัน `setupPermissions` แล้วกด **Run** หนึ่งครั้ง กด Allow ตามที่ระบบถาม
5. **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - คัดลอก URL ที่ได้
6. เอาค่ามาใส่ในไฟล์ `.env` แล้วสั่ง `npm start` ใหม่:

```
PDF_SERVICE_URL="https://script.google.com/macros/s/xxxxx/exec"
PDF_SERVICE_SECRET="รหัสเดียวกับ SHARED_SECRET"
```

## ตอนย้ายขึ้น cloud ของบริษัท

ทำแค่ 3 อย่าง ไม่ต้องแก้โค้ดเลย:

1. ก็อปทั้งโฟลเดอร์ไปวางบน server (ยกเว้น `.env` กับ `.sessions.json`)
2. สร้างไฟล์ `.env` ใหม่บน server ใส่ค่าเดิม (หรือตั้งเป็น environment variable ของระบบก็ได้ ระบบอ่านทั้งสองทาง)
3. `npm start`

สิ่งที่ควรคุยกับทีม IT ตอนนั้น:

- **HTTPS** — ระบบนี้เปิดเป็น HTTP ธรรมดา ถ้าให้เข้าจากนอกออฟฟิศควรมี reverse proxy (nginx / IIS) ครอบเพื่อทำ HTTPS ให้ ไม่งั้นรหัสผ่านวิ่งแบบไม่เข้ารหัส
- **ถ้ารันหลาย process พร้อมกัน** (เช่นใช้ PM2 แบบ cluster) ต้องเปลี่ยน `src/local-state.js` ไปใช้ Redis แทน ไม่งั้นผู้ใช้จะหลุดล็อกอินสลับไปมา — เหตุผลเขียนไว้ในไฟล์นั้นแล้ว

## เรื่องความปลอดภัยที่ควรทำต่อ

**รหัสผ่านยังเก็บเป็นข้อความธรรมดาในชีต Users คอลัมน์ Password**

ระบบเดิมตั้งใจทำแบบนี้เพื่อให้ Admin เปิดดูรหัสของทุกคนได้ ตอนใช้ในวง LAN ยังพอรับได้ แต่ถ้าวันไหนเปิดให้เข้าจากอินเทอร์เน็ต ความเสี่ยงสูงขึ้นมาก — ถ้าไฟล์ชีตหลุดออกไปเมื่อไหร่ รหัสผ่านของทุกคนหลุดตามทันที

โค้ดรองรับรหัสผ่านแบบแฮชอยู่แล้ว (`hashPassword` ใน [src/modules/users.js](src/modules/users.js) และ `login` เทียบได้ทั้งสองแบบ) การเปลี่ยนคือให้ `saveUser` เก็บลง `PasswordHash`/`PasswordSalt` แทน `Password` — บัญชีเดิมจะยังล็อกอินได้ตามปกติ บอกได้เลยถ้าอยากให้เปลี่ยน

## แก้ปัญหาที่พบบ่อย

**`npm start` แล้วขึ้นว่า "ยังตั้งค่าไม่ครบ"**
ยังไม่มีไฟล์ `.env` หรือใส่ค่าไม่ครบ ดูขั้นที่ 3

**ขึ้นว่า "ไม่มีสิทธิ์เข้าถึง Google Sheet"**
ยังไม่ได้แชร์ไฟล์ให้ service account หรือแชร์เป็น "ผู้อ่าน" แทน "ผู้แก้ไข" (ขั้นที่ 2)

**ขึ้นว่า "ขอสิทธิ์เข้าถึง Google Sheets ไม่สำเร็จ: invalid_grant"**
ค่า `GOOGLE_PRIVATE_KEY` ผิดรูปแบบ มักเกิดจากตอนวางแล้วบรรทัดขาด ให้คัดลอกจากไฟล์ JSON มาทั้งบรรทัดโดยไม่แก้อะไร

**เพื่อนร่วมงานเข้าไม่ได้ แต่เครื่องเราเข้าได้**
- Windows Firewall ยังบล็อกอยู่ — ไปที่ Windows Defender Firewall → Allow an app → หา Node.js แล้วติ๊ก Private
- หรืออยู่คนละวง Wi-Fi/LAN กัน (เช่นคนหนึ่งต่อ Wi-Fi แขก) ต้องอยู่วงเดียวกัน

**ปิด PowerShell แล้วระบบดับ**
ปกติครับ หน้าต่างนั้นคือตัวระบบ ถ้าอยากให้รันค้างไว้แม้ปิดหน้าต่าง ให้ทำขั้นที่ 6

**อยากรีเซ็ตแม่แบบฟอร์ม PDF**
ใน Apps Script Editor เลือกฟังก์ชัน `buildCleaningFormTemplate` แล้วกด Run

## สิ่งที่เปลี่ยนไปจากเดิม (นอกจากความเร็ว)

- **เขียนข้อมูลโดยอ้างชื่อคอลัมน์แทนตำแหน่ง** โค้ดเดิมบางจุดวางข้อมูลทั้งแถวตามลำดับที่กำหนดไว้ในโค้ด ซึ่งจะเขียนผิดช่องทันทีถ้าลำดับคอลัมน์จริงในชีตไม่ตรงกัน
- **ปิดบัญชีหรือรีเซ็ตรหัสผ่านแล้วผู้ใช้หลุดทันที** เดิมต้องรอ session หมดอายุเองซึ่งนานถึง 6 ชั่วโมง
- **แก้บั๊กเขตเวลา** รายการของวันที่ 1 ของเดือน/ปี เคยถูกนับเข้าเดือนหรือปีก่อนหน้าในกราฟแนวโน้มและรายงานงบประมาณ
- **แก้บั๊กตัวเลขกลายเป็นวันที่** ค่าอย่าง BTU 36000 หรือค่าล้าง 30000 บาท อยู่ในช่วงเดียวกับรหัสวันที่ของ Sheets พอดี ตอนนี้ระบุคอลัมน์วันที่ไว้ชัดเจนแล้ว
- **ไม่ต้องแคชการตรวจโครงสร้างชีตอีกแล้ว** เดิมต้องแคชไว้ 6 ชั่วโมงเพราะการตรวจแพงมาก ตอนนี้ตรวจได้ฟรีทุกครั้งเพราะใช้ข้อมูลที่โหลดมาอยู่แล้ว
