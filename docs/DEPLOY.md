## 1. เวอร์ชัน Node — ข้อที่พลาดบ่อยที่สุด

ระบบใช้โมดูล `node:sqlite` ที่มากับ Node เอง ซึ่ง**มีตั้งแต่ 22.5.0 ขึ้นไปเท่านั้น**

ถ้าติดตั้งบน Node 18 หรือ 20 (ซึ่งเป็น LTS ที่นิยม) จะดับตั้งแต่บรรทัดแรกด้วย

```
Error: Cannot find module 'node:sqlite'
```

แนะนำ **Node 24 LTS** ตรวจก่อนติดตั้งด้วย `node --version`

## 2. ที่เก็บข้อมูล — ข้อที่พลาดแล้วเสียหายที่สุด

ระบบเขียนไฟล์ตามตารางข้างล่าง **ทั้งหมดต้องอยู่บนดิสก์ถาวร (persistent volume)**

ถ้าปล่อยให้อยู่บนดิสก์ของคอนเทนเนอร์ที่หายเมื่อ deploy ใหม่ → **ข้อมูลเครื่องปรับอากาศทั้งหมดหายทุกครั้งที่ปล่อยเวอร์ชัน**

ตั้งทีเดียวจบด้วย `DATA_DIR`

```bash
DATA_DIR=/mnt/data          # ต้องเป็น volume ที่ผูกไว้ถาวรและเขียนได้
```

จะได้เป็น

| ไฟล์ | ที่อยู่ | คืออะไร |
|---|---|---|
| ฐานข้อมูล | `$DATA_DIR/aircon.db` | ข้อมูลทั้งหมดของระบบ |
| ไฟล์สำรอง | `$DATA_DIR/backups/` | สำรองอัตโนมัติ เก็บ 30 ไฟล์ล่าสุด |
| รูปถ่ายประกอบเอกสาร | `$DATA_DIR/photos/<ชนิด>/<เลขที่เอกสาร>/` | ชนิด = `cleaning` · `repair` · `install` |
| ไฟล์ PDF ของเอกสาร | `$DATA_DIR/docs/<ชนิด>/<ปี>/<เดือน>/` | เก็บเฉพาะฉบับจริง คือใบที่อนุมัติครบ 4 ขั้น หรือใบที่ไม่ต้องอนุมัติ |
| ไฟล์เอกสารที่ช่างถ่ายส่งมา | `$DATA_DIR/attachments/<ปี>/<เดือน>/<เลขที่>/` | ใบที่เขียนมือแล้วแนบรูป |
| Session | `<โฟลเดอร์โปรเจกต์>/.sessions.json` | ผู้ที่ล็อกอินค้างไว้ |

แยกตั้งทีละอย่างก็ได้ด้วย `DB_PATH` · `BACKUP_DIR` · `PHOTO_DIR` · `DOC_DIR` · `ATTACH_DIR` · `SESSION_PATH`

> **Session** ค่าเริ่มต้นยังอยู่ในโฟลเดอร์โปรเจกต์เพื่อความเข้ากันได้กับของเดิม
> ถ้าโฟลเดอร์โปรเจกต์อ่านได้อย่างเดียว ให้ตั้ง `SESSION_PATH=$DATA_DIR/sessions.json`
> ไม่ตั้งก็ยังใช้งานได้ แต่ทุกคนจะหลุดล็อกอินทุกครั้งที่ deploy

## 3. ตัวแปรสภาพแวดล้อม

อ่านจากไฟล์ `.env` ในโฟลเดอร์โปรเจกต์ หรือจาก environment variable ของระบบก็ได้
(ตั้งผ่าน environment variable จะทับค่าในไฟล์ `.env`) **ไม่มีไฟล์ `.env` ก็รันได้**

| ตัวแปร | จำเป็น | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|---|
| `PORT` | ไม่ | `8787` | พอร์ตที่เปิดฟัง |
| `DATA_DIR` | **ควรตั้ง** | โฟลเดอร์ `data/` ในโปรเจกต์ | ที่เก็บข้อมูลถาวร |
| `DB_PATH` | ไม่ | `$DATA_DIR/aircon.db` | ระบุไฟล์ฐานข้อมูลเอง |
| `BACKUP_DIR` | ไม่ | `$DATA_DIR/backups` | ระบุที่เก็บไฟล์สำรองเอง |
| `PHOTO_DIR` | ไม่ | `$DATA_DIR` | รูปถ่ายอยู่ใต้ `<ที่ตั้ง>/photos` อีกชั้น |
| `DOC_DIR` | ไม่ | `$DATA_DIR` | ไฟล์ PDF อยู่ใต้ `<ที่ตั้ง>/docs` อีกชั้น |
| `ATTACH_DIR` | ไม่ | `$DATA_DIR` | ไฟล์แนบอยู่ใต้ `<ที่ตั้ง>/attachments` อีกชั้น |
| `SESSION_PATH` | ไม่ | `.sessions.json` ในโปรเจกต์ | ระบุที่เก็บ session เอง |
| `BROWSER_PATH` | ไม่ | หาเองอัตโนมัติ | ที่อยู่ Chrome/Edge สำหรับแปลงเอกสารเป็น PDF |
| `PUBLIC_URL` | **ตั้งเมื่อเปิดสู่ภายนอก** | ที่อยู่ในวงแลนของเครื่อง | ที่อยู่ที่ใช้ทำลิงก์กรอกเอกสารซ่อมส่งให้ช่าง เช่น `https://aircon.example.co.th` |

**ไม่มีตัวแปรไหนเป็นความลับ** ระบบไม่ต้องใช้ API key หรือ credential ของบริการภายนอกใดๆ

## 4. เน็ตขาออก

**ระบบไม่ต่อเน็ตออกนอกเลย** ไม่มีข้อยกเว้น

บล็อกขาออกทั้งหมดได้โดยไม่กระทบอะไร — ไม่ต้องมีบัญชีหรือคีย์ของบริการภายนอกใดๆ

- ข้อมูลอยู่ในไฟล์ SQLite ในเครื่อง
- เอกสารแปลงเป็น PDF ด้วย Chrome/Edge ที่ติดตั้งอยู่ในเครื่องที่รันระบบ
- รูปถ่าย ไฟล์ PDF และไฟล์เอกสารแนบ เก็บลงดิสก์ในเครื่อง
- หน้าเว็บไม่ดึงไฟล์จาก CDN ใดๆ (ฟอนต์ ไอคอน และไลบรารีกราฟเก็บไว้ในเครื่องหมดแล้ว)

> เดิมการสร้าง PDF และการเก็บไฟล์เอกสารแนบเรียกไปที่ `script.google.com`
> ส่วนนั้นถูกถอดออกทั้งหมดแล้ว ไม่มีโค้ดที่เรียกออกนอกเครื่องเหลืออยู่

## 5. รันเป็นบริการ

```bash
node platform/node.js
```

ควรตั้งให้**เปิดเองเมื่อเครื่องบูต และรีสตาร์ทเองเมื่อโปรเซสตาย**
(systemd, Windows Service, pm2 หรือ restart policy ของคอนเทนเนอร์ — แล้วแต่มาตรฐานขององค์กร)

ตัวอย่าง systemd

```ini
[Unit]
Description=ITEL Aircon Manager
After=network.target

[Service]
WorkingDirectory=/opt/aircon-manager
Environment=DATA_DIR=/mnt/data
Environment=PORT=8787
ExecStart=/usr/bin/node platform/node.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**ตรวจว่ารันอยู่** — เปิด `http://<host>:<port>/` แล้วต้องได้หน้าเข้าสู่ระบบ
(ยังไม่มี endpoint สำหรับ health check โดยเฉพาะ ถ้าต้องการแจ้งมาได้)

## 6. การสำรองและกู้คืน

**สำรองอัตโนมัติอยู่แล้ว** — ทุกครั้งที่เปิดเซิร์ฟเวอร์ และทุก 24 ชั่วโมง
และก่อนงานที่เสี่ยง (นำเข้าข้อมูลเครื่อง · อัปเดตแผนปีจากรายการเครื่อง · ลบแผนล้างทั้งปี)
เก็บ 30 ไฟล์ล่าสุดใน `$DATA_DIR/backups` (ไฟล์ละราว 1–2 MB)

ยังแนะนำให้มีสำรองระดับองค์กรอีกชั้น เพราะไฟล์สำรองอยู่บนเครื่องเดียวกับตัวจริง

> ⚠️ **การสำรองอัตโนมัติครอบคลุมเฉพาะฐานข้อมูล ไม่รวมรูปถ่ายและไฟล์ PDF**
>
> รูปถ่ายประกอบเอกสารอยู่ที่ `$DATA_DIR/photos/` ซึ่งโตขึ้นเรื่อยๆ
> (ประมาณการจากข้อมูลจริง: เครื่อง 457 ตัว ล้างปีละ 3 รอบ รูปละราว 300 KB
> = **ราว 3.5 GB ต่อปี**) การใส่ไฟล์ขนาดนี้ลงในไฟล์สำรองทุกวันไม่คุ้ม
>
> ไฟล์ PDF ที่ `$DATA_DIR/docs/` โตอีกราวเท่าตัวของรูป เพราะรูปถูกฝังลงในไฟล์
> รวมแล้ว **ราว 7 GB ต่อปี** — เผื่อพื้นที่ดิสก์ไว้ตามนี้
>
> **สองโฟลเดอร์นี้ต้องอยู่ในระบบสำรองไฟล์ของบริษัท** เช่นเดียวกับข้อมูลอื่นบนเซิร์ฟเวอร์
> ถ้า `docs/` หายไม่เสียหายอะไร ระบบสร้างไฟล์ใหม่ได้จากข้อมูลในฐานข้อมูลกับรูป
> แต่ถ้า `photos/` หาย รูปจะหายจริง เหลือแต่ตัวเอกสารและข้อมูลการล้างในฐานข้อมูล

**กู้ทั้งระบบ** — หยุดบริการ เอาไฟล์สำรองมาแทน `aircon.db` แล้วเปิดใหม่

```bash
systemctl stop aircon-manager
cp /mnt/data/backups/aircon-YYYY-MM-DD_HHMMSS-*.db /mnt/data/aircon.db
systemctl start aircon-manager
```

> ต้องหยุดบริการก่อนเสมอ และอย่าลืมลบไฟล์ `aircon.db-wal` / `aircon.db-shm` ที่ค้างอยู่

**กู้เฉพาะเครื่องที่ถูกลบ** — ไม่ต้องหยุดบริการ

```bash
node scripts/restore-air-unit.mjs <รหัสเครื่อง>            # ดูก่อนว่าจะกู้อะไร
node scripts/restore-air-unit.mjs <รหัสเครื่อง> --apply    # กู้จริง
```

## 7. ข้อควรทราบด้านความปลอดภัย

- **ระบบให้บริการผ่าน HTTP** ไม่ได้ทำ TLS เอง ต้องวางหลัง reverse proxy ที่ทำ HTTPS ให้
- **รหัสผ่านผู้ใช้เก็บเป็นค่าแฮช PBKDF2** (แปลงครบทุกบัญชีเมื่อ 22/09/2026)
  ไฟล์สำรองที่สร้างก่อนวันนั้นมีรหัสผ่านแบบข้อความธรรมดา (ในเครื่องทดสอบถูกหมุนเวียนออกไปหมดแล้ว
  แต่ถ้าเคยคัดลอกไฟล์สำรองเก่าไปไว้ที่อื่น ควรลบ) โปรดจำกัดสิทธิ์การเข้าถึงโฟลเดอร์ข้อมูลไว้เฉพาะบัญชีที่รันบริการ
- ระบบมีระบบผู้ใช้/สิทธิ์ในตัว แบ่งตามภูมิภาค ตามเมนู และตามงานที่มอบให้ผู้รับเหมา (ตรวจที่เซิร์ฟเวอร์ทุกคำสั่ง)
